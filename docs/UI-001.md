## Purpose

Deliver the smallest responsive PySide6 desktop workflow that proves the M1 local RAG
loop without command-line database manipulation:

```text
create/select workspace
-> select one anonymous synthetic digital PDF
-> import/extract/chunk/embed/activate locally
-> submit one question against that exact active document version
-> reuse RAG-001 and RAG-002 through CHAT-001
-> show a grounded answer or an explicit non-answer
-> open the validated citation snapshot when one exists
```

UI-001 is a thin desktop integration ticket. It does not move persistence, security,
retrieval, sufficiency, citation validation, model selection, or transaction authority
into Presentation.

## M1 User-Visible Completion Criterion

With the exact configured local models already cached and the approved development/test
security provider selected, an evaluator can launch LexLocal, create or explicitly
select a workspace, import one anonymous synthetic native-text PDF through a file
picker, observe truthful processing stages until the document is ready, enter one
question, receive either a completed grounded answer with validated citations or one of
the two explicit non-answer outcomes, and open a citation-detail view showing the exact
retrieval-time document/version/page/excerpt snapshot. The GUI remains responsive and
supports cooperative cancellation while long work runs.

The demonstration uses no SQL, database seeding, direct repository calls, model
preparation/download, cloud fallback, or private/legal document.

## Repository Evidence and Current Position

### Desktop startup

- `python -m lexlocal` enters `src/lexlocal/__main__.py`, which delegates to
  `lexlocal.bootstrap.application.run`.
- `run` loads validated settings, configures logging, runs SQLite migrations, composes
  workspace behavior, resolves both local models, creates `QApplication` and
  `MainWindow`, enters the event loop, and closes the process-owned model runtime on
  exit or event-loop failure.
- `create_application` owns `QApplication` reuse/creation and returns one `MainWindow`.
- `MainWindow` is currently a 960x640 `QMainWindow` with only a centered `LexLocal`
  label. No usable desktop workflow exists.
- Persistence/migration and model composition failures currently prevent the window
  from being shown. `compose_local_models` closes a partial runtime and raises typed
  `LocalModelUnavailable`, `LocalModelIncompatible`, `LocalModelRuntimeError`, or
  `LocalModelPersistenceError`; it never substitutes/downloads. The adapter can also
  surface a persisted-identity adoption conflict as `LocalModelRuntimeError`, so UI-001
  must classify by composition stage: runtime initialize/resolve/load/health failures
  become a visible disabled capability state, while settings/migration/security/local-
  model repository and persisted-identity integrity failures remain fatal.
- `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen`; the existing startup test
  creates and closes a real `QApplication`/`MainWindow` without pytest-qt.

### Presentation architecture

- `src/lexlocal/presentation/` contains only the placeholder window and package files.
  There is no controller, presenter, display-state value, worker, signal convention,
  navigation system, or error renderer to reuse.
- The approved architecture permits Presentation to depend on Application and Domain,
  and forbids Presentation dependencies on concrete Infrastructure or Bootstrap.
- The repository has no asyncio/Qt integration and no worker framework. A UI-001-local
  bounded Qt worker design is therefore required; a generic job platform is not.

### Workspace workflow

- `CreateWorkspace(display_name, profile=None)` creates and commits one ACTIVE
  workspace with injected ID/time.
- `ListWorkspaces()` returns normal ACTIVE workspaces through the UoW.
- `SelectWorkspace(workspace_id)` verifies the persisted workspace is ACTIVE and then
  mutates the shared Application-owned `ActiveWorkspaceScope`.
- `ActiveWorkspaceScope.require_workspace_id()` is the sole downstream scope source.
- `Workspace.state == ACTIVE` means the persisted workspace permits normal mutation;
  it does not mean the workspace is selected. The UI must render the explicit selected
  scope separately.
- Workspace display names are decoded through the existing workspace persistence
  boundary. Presentation needs no SQLite or codec access.

### Single-PDF document workflow

- `ImportSyntheticPdf(source: bytes, logical_filename: str)` is the public Application
  ingestion entry point. It validates exact bytes through `PdfInspector`, hashes and
  stores those same bytes unchanged, detects same-workspace duplicates, and atomically
  creates the document/version/job/blob graph.
- The use case accepts bytes, not a path. It intentionally exposes no original path.
  No existing adapter reads a user-selected external file.
- `ProcessNativePdfText(IngestionResult)` reads only the controlled copy, extracts exact
  native page text, persists pages/locators, and returns a `ProcessingResult` at
  `PROCESSING/CHUNKING`.
- `PrepareIndexing(ProcessingResult)` deterministically produces/reuses either a
  `StagingEmbeddingHandoff` or a compatible `ReusedActiveIndex`.
- `EmbedStagingChunks` generates only missing embeddings, verifies completeness, and
  calls INDEX's `FinalizeIndexing`, the sole activation authority. Success returns an
  `ActivatedIndex` whose job is `READY` or `READY_WITH_WARNINGS`.
- The individual use cases are real and composable, but there is no Application command
  that owns their import-to-ACTIVE ordering or exposes a safe aggregate result/status
  to Presentation.
- Ingestion has no cancellation port. Its storage/registration failure path rolls back
  and compensates stored bytes, while a successful call has already committed the
  QUEUED document/version/job graph before returning.
- `ProcessNativePdfText` turns cancellation before start or during extraction/staging
  into persisted `CANDIDATE_CANCELLED`/`CANCELLED`; `PrepareIndexing` can leave a
  committed reusable STAGING generation when its final checkpoint cancels; embedding
  commits compatible batches independently and delegates the sole atomic activation to
  `FinalizeIndexing`.
- `ux_workspace_duplicate_live_source` covers every non-DELETED version, including
  FAILED/CANCELLED candidates. No current command deletes, repairs, or reconstructs an
  incomplete document for UI retry, so same-source retry after registration is not an
  M1 UI capability.
- M1 supports one digital/native-text PDF only. OCR, images, multi-file import,
  replacement, restart reconstruction, persisted diagnostics, and processing recovery
  are owned by later tickets.

### Processing and status

- Authoritative persisted states already exist for document versions, processing jobs,
  pages, and index generations. UI-001 must not duplicate their transition rules.
- No approved Application query currently lists documents or reconstructs an arbitrary
  persisted job for a UI status screen.
- The current in-process vertical slice does return every handoff required to derive
  truthful stage changes and the final READY/READY_WITH_WARNINGS state. UI-001 therefore
  uses typed in-process workflow-stage notifications and final Application results;
  it does not query raw tables or add a document dashboard/polling API.
- Numeric progress is not consistently exposed by existing use cases. The UI must show
  named phases only.

### CHAT precondition and QA scope

- CHAT-001's `CompleteChat` accepts only `QaRequestId`. Its repository reconstructs an
  already committed ACTIVE chat, USER question message, QA request, and non-empty exact
  `qa_scope_versions` snapshot.
- No production Application use case currently creates any of those records. Every
  current test that needs them inserts them as fixture SQL. UI must not repeat that.
- The initial schema already contains `chats`, `chat_scope_documents`,
  `chat_messages`, `qa_requests`, and `qa_scope_versions`; no migration is required.
- For this one-document M1 workflow, the exact scope is repository-determined: the
  `DocumentId` and ACTIVE `DocumentVersionId` returned by the successfully activated
  document workflow. The intake command must revalidate active workspace/document/
  version/index ownership inside one UoW before committing the chat, user message,
  DRAFT QA request, and immutable one-version QA scope.
- A one-question chat may also snapshot its one logical document in the existing
  `chat_scope_documents` table; `qa_scope_versions`, not that mutable chat scope, remains
  authoritative for RAG-001.
- The schema has identity/ownership constraints but no logical uniqueness rule that
  prevents a second QA request created with fresh IDs for the same question. Therefore
  the planned intake must materialize one attempt before writing, reconstruct by that
  same `QaRequestId`, and the worker must never call intake again after a compatible
  commit. This is Application/worker idempotency, not a new migration.

### RAG-001, RAG-002, and CHAT-001

- Presentation calls neither `EmbedQuery` nor retrieval/sufficiency providers.
- `CompleteChat` invokes `PrepareRetrieval` exactly once for an incomplete eligible QA,
  passes that exact registration to RAG-002, skips answer-model inference for both
  non-sufficient states, strictly validates sufficient structured output/citations, and
  commits the retrieval/verifier/answer/citation graph atomically.
- `ChatCompletionResult.graph` exposes the terminal evidence state, protected answer or
  Application-authored non-answer, exact ordered citations, and exact retrieval
  evidence snapshots. `reused` identifies compatible terminal reuse.
- A retry using the same `QaRequestId` can reuse a compatible terminal graph without
  retrieval/model/write work. UI-001 must retain that ID after failure/cancellation;
  it must not create a fresh QA request merely to retry.
- `CompleteChat` explicitly accepts clean `DRAFT`, `FAILED`, and `CANCELLED` targets.
  It records cancellation/failure only after loading an eligible target; therefore a QA
  intake committed before `CompleteChat` is invoked may truthfully remain `DRAFT`.
  `FAILED`/`CANCELLED` require their matching safe failure metadata, while partial or
  conflicting state fails closed.
- Sanitized failures exist throughout the layers, but there is no UI message-key mapper.

### Citation opening

- Every returned citation owns an `EvidenceItemId` and one-based ordinal. The same
  terminal graph contains the matching retrieval evidence with snapshot document name,
  version number, page number, `SourceLocator`, and exact full excerpt.
- That is sufficient for an in-app citation detail view without a database query.
- No current Application citation resolver returns source PDF bytes or a controlled
  source reference. The development controlled-source provider is process-memory-only,
  and the approved secure source viewer/page navigation work belongs to STORAGE-003.
- UI-001 therefore must not promise `QPdfView`, system-viewer launch, exact geometric
  highlighting, physical path opening, or restart-safe source reconstruction.

## Frozen Decisions

1. **One-window structure.** M1 uses one `QMainWindow` with three visible sections in
   workflow order: Workspace, Document, Chat. No navigation framework or history view is
   justified. Citation details use one small modal/non-modal detail dialog owned by the
   main window.
2. **Explicit workspace selection.** Creating a workspace refreshes the list but does not
   equate persisted `WorkspaceState.ACTIVE` with process selection. The user explicitly
   selects it; the UI displays its safe name and disables document/chat actions when
   `ActiveWorkspaceScope` is empty. Selection is not persisted across restart.
3. **One synthetic native PDF.** `QFileDialog.getOpenFileName` is single-select and
   filtered to PDF. The GUI chooses a path but does not read it. A worker-side
   Infrastructure adapter behind an Application port reads exact bytes and derives only
   the basename; path/source bytes are private, non-persistent inputs.
4. **Application-owned document orchestration.** A small coordinator calls the existing
   ingestion, processing, indexing, and embedding/finalization use cases in that exact
   order and returns one typed active-document result. Presentation never sequences or
   reimplements pipeline decisions. Cancellation observed before the uninterruptible
   ingestion call starts leaves no new graph. Ingestion itself has no cancellation port:
   a request arriving during storage/registration may therefore commit the graph. After
   that call returns, the coordinator must invoke `ProcessNativePdfText` without an
   intervening cancellation checkpoint so processing can record its approved terminal
   cancellation. Ingestion failure/duplicate compensation leaves no new graph. After
   processing starts, cancellation/failure may truthfully leave a registered inactive
   graph or compatible STAGING/partial-embedding work; UI-001 does not repair or delete
   it. Once final activation has committed and returned, READY wins and no later
   coordinator checkpoint may relabel that completed document as cancelled.
5. **M1 QA intake.** A focused Application command atomically creates one ACTIVE chat,
   one sequence-1 USER message, one DRAFT QA request, one logical-document chat scope,
   and one immutable exact `qa_scope_versions` row for the just-activated version. It
   revalidates same-workspace ACTIVE document/version/index ownership and encodes the
   question through the existing codec. It materializes one immutable intake attempt
   (including its injected IDs) before the write, returns its `QaRequestId` only after
   commit, and can reconstruct/reuse only that exact compatible attempt by ID after an
   ambiguous delivery. Partial/conflicting state fails closed. It adds no general chat
   lifecycle API.
6. **Exact one-document scope.** The ready document returned by the current session is
   the only QA scope. UI cannot widen it, inject IDs, or select an archived/candidate
   version. RAG-001 still treats `qa_scope_versions` as authoritative.
7. **Truthful progress only.** Document statuses are `Importing…`, `Extracting text…`,
   `Building index…`, `Generating embeddings…`, `Ready`, `Ready with warnings`,
   `Cancelling…`, `Cancelled`, or `Failed`. Question statuses are `Preparing question…`,
   `Asking…`, `Cancelling…`, `Cancelled`, or `Failed`. No fake percentage, token stream,
   provider phase, or table-derived guess is shown.
8. **One serialized M1 worker thread.** One long-lived `QObject` worker on one `QThread`
   owns the complete M1 composition after persistence/security startup. It serializes
   external-file IO, PDF work, SQLite use cases, embeddings, RAG, verifier, and answer
   inference. This is the smallest bounded worker that also preserves the documented
   single model-execution owner; M1 does not add `QThreadPool` or a generic executor.
9. **GUI-thread purity.** Only the GUI thread creates/mutates widgets, opens native Qt
   dialogs, and maps immutable results to display state. Worker signals carry typed
   Application/Domain results or sanitized UI error codes, never connections, rows,
   SDK objects, prompts, payloads, or raw exceptions.
10. **Cooperative cancellation.** A thread-safe per-operation cancellation source can be
    set directly from the GUI thread even while the worker event loop is busy. Narrow
    adapters raise each existing use case's approved cancellation type. There is no
    `QThread.terminate`, provider interruption, or false claim of immediate cancellation.
    A late provider result is discarded by existing checkpoints. If QA intake has
    committed, the worker retains its `QaRequestId` and still enters `CompleteChat` with
    cancellation already requested so CHAT can record `CANCELLED`. If shutdown or a
    worker/dispatch failure prevents that call, no CHAT failure state is fabricated: the
    valid DRAFT and its immutable scope remain the same retry target. Inactive document/
    index rows may remain exactly as PROCESSING/INDEX/EMBEDDING permit; UI-001 adds no
    cleanup/recovery framework and never calls them READY.
11. **One question, existing CHAT authority.** After committing the QA precondition,
    the worker invokes only `CompleteChat(qa_request_id)`. It never calls RAG or RAG-002
    directly. A failed/cancelled question retains the same QA ID for explicit Retry;
    completed results disable new submission in this M1 window.
12. **Outcome rendering.** `SUFFICIENT` shows the exact protected assistant content and
    ordered validated citation controls. `RELATED_BUT_INSUFFICIENT` shows the exact
    Application non-answer and policy-approved related citations. `INSUFFICIENT` shows
    the exact Application non-answer and no citations. Presentation does not reinterpret
    scores, relations, confidence, or sufficiency.
13. **Citation opening means validated snapshot detail in M1.** Open Citation resolves
    the selected `CitationId`/`EvidenceItemId` only inside the returned terminal graph
    and displays snapshot document name, version, one-based page, and exact full excerpt.
    It does not expose internal IDs/scores/path by default and does not open/decrypt a
    PDF. STORAGE-003 owns the later source viewer.
14. **Model state and no setup.** Worker initialization composes the exact configured
    cached chat and embedding models at most once. READY enables document work. Typed
    unavailable/incompatible/runtime failure closes any partial runtime and produces the
    sanitized nonfatal `MODEL_UNAVAILABLE` state: workspace behavior remains usable but
    Import/Ask stay disabled until process restart after separately approved preparation.
    Classification is by owning boundary, not exception class alone: runtime
    initialize/resolve/load/health failures are capability failures, while settings,
    migration, security-provider, SQLite/local-model repository, or persisted-identity
    adoption/conflict failures are `FATAL_STARTUP` even when an adapter surfaces a
    `LocalModelRuntimeError`. UI never retries composition in-process, downloads,
    prepares, substitutes, or inspects SDK objects.
15. **Error presentation.** Presentation maps exception classes/categories to fixed
    user-facing message keys and actions. It never renders `str(exception)` from
    Infrastructure/provider/database failures. Detailed content is neither logged nor
    placed in tooltips.
16. **Retry/idempotency.** Workspace commands use existing behavior. Duplicate PDF is a
    visible non-success. When cancellation is observed before ingestion starts, or
    ingestion fails/compensates without registration, retry may select/import again.
    After registration, document cancellation/failure never appears READY and the current
    session offers no document retry because the duplicate-live-source constraint covers
    incomplete/FAILED/CANCELLED versions; durable recovery/cleanup is deferred. A
    committed intake is never recreated: DRAFT starts `CompleteChat`, FAILED/CANCELLED
    retry through `CompleteChat`, and compatible terminal state reuses the result, all
    with the same `QaRequestId`, exact question, and immutable `qa_scope_versions`.
17. **Stale-result protection.** Every worker command carries an opaque operation number
    and selected-workspace epoch. Selection/import/question controls are disabled while
    conflicting work runs, and the controller still ignores any result whose token or
    workspace epoch is no longer current.
18. **Shutdown.** Window close stops new submissions, requests cooperative cancellation,
    and waits for the current worker call to return; it does not force-kill inference.
    The worker closes the sole local-model composition on its owning thread, then quits
    and joins the `QThread`. A close may visibly remain pending while an uninterruptible
    provider call finishes. If intake committed, its ID is retained until the worker has
    either entered CHAT cancellation handling or reported that the exact DRAFT remains.
    The same DRAFT rule applies to a non-CHAT worker/dispatch failure in this gap;
    Presentation must not mark it FAILED because `CompleteChat` never owned an operation
    to fail. UI-001 makes no restart/history promise for an unexpectedly terminated
    process.
19. **Security boundary.** UI-001 remains development/test synthetic-only and shows a
    persistent development warning. Production/release composition still fails before
    protected/model workflow. UI stores no source/question/answer/excerpt/path in

## Presentation State Model

These are immutable display states derived from typed Application results and worker
events. They are not a second persisted business state machine.

### Capability state

| State | Meaning / rendering |
|---|---|
| `STARTING` | Persistence/security/model session is initializing; all workflow actions disabled. |
| `READY` | Exact chat and embedding models are READY and the synthetic workflow may run. |
| `MODEL_UNAVAILABLE` | Typed missing/uncached/incompatible/runtime failure after healthy persistence/security; partial runtime is closed, fixed local-only guidance is shown, workspace remains usable, Import/Ask are disabled, and no in-process retry/download exists. |
| `FATAL_STARTUP` | Settings, migration/database, security configuration, model-registry persistence/integrity, or unexpected composition failure; protected/model workflow disabled and only a sanitized startup message/close action shown. |

### Workspace state

| State | Valid transition / action |
|---|---|
| `NO_SELECTION` | Initial after list load; create/select enabled when no worker operation runs. |
| `CREATING` | Create/select controls disabled until created or failed. |
| `SELECTED` | Safe display name shown; document import becomes eligible when capability READY. |
| `FAILED` | Fixed sanitized message; return to `NO_SELECTION` or previous `SELECTED`. |

Selecting a different workspace clears all session-only document/question/citation
display state and increments the workspace epoch. Selection is disabled while a
document/question job is active.

### Document state

| State | Source | UI behavior |
|---|---|---|
| `EMPTY` | No successful import in current selected-workspace session | Import enabled only with selected workspace + READY models. Chat disabled. |
| `IMPORTING` | Coordinator before/through ingestion | Show `Importing…`; Cancel enabled. |
| `EXTRACTING` | Coordinator before native processing | Show `Extracting text…`; Cancel enabled. |
| `INDEXING` | Coordinator before chunk/candidate preparation | Show `Building index…`; Cancel enabled. |
| `EMBEDDING` | Staging handoff before embedding/finalization | Show `Generating embeddings…`; Cancel enabled. |
| `READY` | Activated result with job READY | Safe document name/page count; question input enabled. |
| `READY_WITH_WARNINGS` | Activated result with job READY_WITH_WARNINGS | Same as READY plus truthful warning badge; no invented warning details. |
| `CANCELLING` | Cancellation requested | Import/Ask disabled; Cancel disabled; wait for worker terminal signal. |
| `CANCELLED` | Typed cancellation | Never treated as ready. If no registration committed, return to EMPTY and allow a new selection; if registration committed, show registered-incomplete and disable document retry for this session. |
| `FAILED` | Typed sanitized failure | Never treated as ready. Reader/import failure without registration may return to EMPTY; post-registration failure shows registered-incomplete with no retry/recovery action. |

### Question/result state

| State | UI behavior |
|---|---|
| `IDLE` | Non-whitespace question allowed only for READY document/capability. |
| `PREPARING` | Materialize one intake attempt, atomically commit the exact precondition, and retain its `QaRequestId` before any cancellation is rendered. |
| `ASKING` | CHAT-001 owns retrieval, sufficiency, optional inference, and final commit. |
| `CANCELLING` | Cancellation requested; late output is never rendered. |
| `GROUNDED` | Render exact answer and ordered citations. |
| `RELATED_NON_ANSWER` | Render exact Application non-answer and ordered related citations. |
| `INSUFFICIENT_NON_ANSWER` | Render exact Application non-answer; zero citations. |
| `FAILED` | Render sanitized failure. If intake committed but completion never started, the persisted target remains DRAFT; if CHAT owned the failed work it is FAILED. Retry invokes `CompleteChat` with that same QA request and never runs intake again. |
| `CANCELLED` | Render cancelled; Retry invokes `CompleteChat` with the same CANCELLED/DRAFT QA request and immutable scope. |

### Enable/disable rules

| Action | Enabled when |
|---|---|
| Create Workspace | Startup not fatal, no active worker operation, non-whitespace name. |
| Select Workspace | Existing ACTIVE item selected and no active worker operation. |
| Import PDF | Capability READY, workspace selected, document state EMPTY, no operation, and no registered-incomplete document is retained for the session. |
| Cancel processing | Document state IMPORTING/EXTRACTING/INDEXING/EMBEDDING only. |
| Ask | Capability READY, document READY/READY_WITH_WARNINGS, question non-whitespace, no QA yet, no operation. |
| Retry question | Same QA ID exists in eligible DRAFT/FAILED/CANCELLED state and no operation; never create another intake. |
| Cancel question | Question PREPARING/ASKING only. |
| Open citation | Terminal grounded/related result and one validated citation selected. |

## Threading Model

### Blocking-operation inventory

| Operation | Classification | Required handling |
|---|---|---|
| Native `QFileDialog` interaction | GUI-thread safe/required | Open on the GUI thread; return the selected path as an ephemeral input only. |
| Widget validation and immutable display-state reduction | GUI-thread safe | Keep bounded and free of filesystem, database, model, or payload work. |
| Settings, migration, and security-provider bootstrap | Blocking startup boundary | Complete before normal protected workflow is enabled; show only a fixed fatal state on failure. |
| Workspace list/create/select | Must run outside GUI thread | Execute Application use cases on the serialized workflow worker; deliver immutable results. |
| Selected-file stat/read and basename derivation | Must run outside GUI thread | Infrastructure adapter behind the Application port; never log or persist the physical path. |
| PDF inspection, hashing, controlled storage, and ingestion registration | Must run outside GUI thread | Existing ingestion contracts through the document coordinator. |
| Native extraction and page persistence | Must run outside GUI thread | Existing processing use case and cancellation contract. OCR is not invoked. |
| Chunking, candidate persistence, embedding, and index activation | Must run outside GUI thread | Existing INDEX/EMBEDDING paths; no alternate activation authority. |
| Foundry runtime initialization, readiness checks, and inference | Must run outside GUI thread | One worker-owned process composition; cached/local-only and no fallback. |
| QA-intake and all other nontrivial SQLite/UoW work | Must run outside GUI thread | Application command using short caller-owned UoWs. Connections never cross threads. |
| RAG retrieval, evidence verification, and CHAT completion | Must run outside GUI thread | Invoke only through `CompleteChat`; no UI-owned sub-steps. |
| Citation snapshot lookup in the already returned immutable graph | GUI-thread safe | Bounded identity lookup and widget rendering only; no repository/source access. |
| Physical source/PDF opening | Unsupported in current evidence | Out of scope; STORAGE-003 must provide the future safe resolver/viewer boundary. |
| Cancellation request flag | GUI-thread safe | Set the thread-safe per-operation source directly; owning use cases observe it cooperatively. |

No audited blocking operation remains classified as uncertain: unsupported physical
source opening is excluded, and every implemented IO/model/database path is assigned to
the single worker. If a future API proves to require thread affinity different from this
inventory, that implementation step must stop for an ownership review.

### GUI thread

- Own `QApplication`, `MainWindow`, widgets, `QFileDialog`, citation dialog, controller,
  immutable display state, enablement, and safe text rendering.
- Submit commands with operation/workspace-epoch tokens.
- Set the thread-safe cancellation source directly.
- Receive queued signals and reject stale tokens before touching widgets.
- Never read the PDF, open SQLite/UoWs, call model/provider, or mutate worker objects
  directly other than the cancellation source's thread-safe `cancel()`.

### Workflow worker thread

- One `QObject` is moved to one long-lived `QThread`.
- Its initialization slot builds the worker-owned M1 composition, including the sole
  Foundry runtime/provider lifetime. No second provider/runtime exists.
- Slots serialize list/create/select workspace, document workflow, QA intake,
  `CompleteChat`, and shutdown. SQLite UoWs continue to create their own connection for
  each use case; no connection crosses threads.
- The worker translates only at its outer boundary to fixed presentation error codes.
  Original sanitized Application exception categories may be classified but not emitted
  as arbitrary text or chained exceptions.

### Signals

The exact Qt class names may follow repository naming during Step 3, but the observable
contract is fixed:

- initialized/capability status;
- workspace list/create/select completed;
- document phase changed;
- document ready, cancelled, or failed;
- question prepared (safe QA identity retained internally), completed, cancelled, or
  failed;
- shutdown complete.

Every signal includes its opaque operation number and workspace epoch. Signals carry
immutable SDK/SQLite-free values. The question, answer, excerpt, and display name are
allowed only in the specific private result DTO sent to the GUI for rendering; they are
never diagnostic metadata or log fields.

### Cancellation adapters

One per-operation `threading.Event`-style source is shared by narrow adapters for the
existing processing, indexing, embedding, RAG-002, and CHAT cancellation protocols.
Each adapter raises the exact owning exception; generic exceptions must not be used to
simulate cancellation. The source resets only when the prior operation is terminal.

File read and ingestion are not forcibly interrupted. Cancellation observed before the
ingestion call prevents registration. Cancellation arriving while ingestion is running
cannot stop that use case; if ingestion returns a committed registration, the
coordinator immediately invokes `ProcessNativePdfText` with the cancellation source
still set and adds no checkpoint that could strand a QUEUED graph. Processing then owns
terminal cancellation recording. Later INDEX/EMBEDDING cancellation keeps its existing
fail-closed semantics. After final activation returns, the committed READY result wins
and no coordinator checkpoint may relabel it cancelled. Foundry inference is also not
forcibly interrupted; existing post-inference checks discard late output.

### Shutdown

`closeEvent` requests cancellation and temporarily ignores close while work is active.
When the worker returns, it closes the process-owned model composition on the same
thread, emits shutdown complete, quits the thread event loop, and the GUI waits for the
thread before final close. Tests must prove no `QThread: Destroyed while thread is still
running` warning and no forced termination path.

## Error and Privacy Model

Presentation maps typed failures to stable safe categories, not raw exception text:

| Failure | Minimal user-visible state |
|---|---|
| No active workspace | `Select a workspace first.` |
| Invalid/unsupported/unreadable/protected PDF | `The selected PDF cannot be imported.` |
| Duplicate document | `This PDF is already registered in the selected workspace.` |
| No usable native text | `This PDF has no usable native text in M1; OCR is unavailable.` |
| Processing/index/embedding persistence failure before registration | `Document processing failed; no document was registered.` Import remains available. |
| Processing/index/embedding failure after registration | `Document processing failed; the registered document is incomplete and is not ready.` No same-session retry/cleanup is offered. |
| Processing cancellation before registration | `Document processing was cancelled; no document was registered.` Import remains available. |
| Processing cancellation after registration | `Document processing was cancelled; the registered document is incomplete and is not ready.` No same-session retry/cleanup is offered. |
| Model unavailable/runtime failure | `Required local models are unavailable. No cloud fallback was used.` |
| No eligible index/retrieval integrity failure | `The document index is unavailable or inconsistent.` |
| CHAT provider/output/persistence failure | `The question could not be completed.` |
| CHAT cancellation | `The question was cancelled; no completed answer was saved.` |
| RELATED_BUT_INSUFFICIENT | Exact Application-authored non-answer plus related citations. |
| INSUFFICIENT | Exact Application-authored non-answer; no citations. |
| Citation missing/corrupt in returned graph | Disable/open failure with `Citation is unavailable`; never reconstruct or guess. |
| Fatal settings/migration/security startup | Restricted fixed startup failure, no protected/model workflow. |

The actual copy should be centralized as message keys/constants in Presentation; no
localization framework is added. Full filesystem paths appear only in the native file
picker and are not echoed into the main UI, logs, or errors. User-visible workspace name,
question, answer, and citation excerpt are rendered because the user explicitly owns
that screen, but are not copied to telemetry, logs, clipboard, widget object names, or
test IDs.
